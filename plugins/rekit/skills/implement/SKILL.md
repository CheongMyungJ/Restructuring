# 재개발 키트로 구현하기

키트 경로: `$ARGUMENTS` (없으면 `./kit`). 레거시 코드가 함께 있으면(예: `./legacy/`) 키트와 대조하는 근거로 쓴다.

## 시작
1. `kit/README.md` → `00_overview.md` → `02_architecture.md` → `03_interfaces/`(외부 계약) → `08_decisions.md`(사람이
   확정한 사항) → `09_open_questions.md`(미해결 질문과 적용 가정) → `10_plan.md` 순서로 읽는다.
2. 목표 스택·저장소 구조가 키트나 사용자 지시에 없으면 사용자에게 확인한다. 미해결 질문 중 `blocking`이 남아 있으면
   적용 가정을 사용자에게 보여주고 진행 여부를 확인한다.

## 진행 (10_plan.md의 태스크 순서대로)
각 태스크 T-NNN마다:
1. 태스크에 적힌 컨텍스트 팩(키트 파일/ID)만 읽는다. 필요한 경우에만 다른 ID를 추가로 연다.
2. `계약(유지 필수)` 항목은 이름·포맷·바이트·순서·반올림·시간대·인코딩·오류코드까지 정확히 지킨다. `구현상세(변경 가능)`은
   더 나은 설계로 바꿔도 되지만 관측 가능한 동작은 같아야 한다.
3. 해당 규칙의 테스트 벡터(TV-*)를 먼저 테스트로 옮기고 구현한다(TDD).
4. `07_tests/`의 골든(특성화) 테스트가 있으면 태스크 완료 기준에 맞춰 실행해 통과시킨다.
5. 키트가 모호하면: 레거시 코드가 있으면 `src:` 참조를 따라 확인하고, 없으면 `09_open_questions.md`의 적용 가정을
   따른다. 결정 사항은 `IMPLEMENTATION_NOTES.md`에 ID와 함께 기록한다.
6. 태스크 완료 시 진행 로그(`IMPLEMENTATION_PROGRESS.md`)에 결과·테스트 상태를 남긴다.

## 마무리
- 전체 테스트와 `07_tests` 골든 테스트를 모두 실행해 결과를 보고한다.
- 키트의 모든 계약(03_interfaces) 목록을 하나씩 대조해 누락이 없는지 점검한다.
- 키트와 다르게 구현한 부분, 남은 가정·위험을 요약한다.
