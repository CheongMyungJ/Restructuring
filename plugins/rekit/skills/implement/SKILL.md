# 재개발 키트로 재설계·구현하기

키트 경로: `$ARGUMENTS`의 첫 인자 (없으면 `./kit`).
**레거시 코드는 새 프로젝트 작업 공간에 두지 않는다.** 실험상 레거시 코드가 손에 있으면 규칙을 알려 줘도 상당 부분 이식이
일어났고(구조 유사도 LSS 24~82), 키트만으로는 동작 만점과 낮은 LSS(6~20)를 함께 얻었다. 모호점은 `legacy_ref/`로 푼다.
사용자가 레거시 코드를 굳이 제공하면 아래 5·마무리 절차를 반드시 지킨다.

키트는 세 층으로 되어 있다. 이 구분이 구현 방식의 핵심이다.
- **명세(spec)** — 키트 루트 `00`~`09`: 무엇을 지켜야 하는가(외부 계약·관측 가능한 동작·테스트). 레거시 구조와 무관하게 쓰여 있다.
- **목표 설계(design/)** — 레거시 코드를 보지 않고 명세만으로 만든 새 구조(구성요소 C-*, ADR, 할당표).
- **레거시 참고(legacy_ref/)** — 레거시가 어떻게 했는가. 특정 모호점을 풀 때만 본다. 구조 템플릿이 아니다.

## 시작
1. `kit/README.md` → `00_overview.md` → `02_constraints.md` → `03_interfaces/` → `04_data/` → `05_behavior/`(필요한
   기능만) → `08_decisions.md` → `09_open_questions.md` → `design/` → `10_plan.md` 순서로 읽는다.
2. 목표 스택·저장소 구조가 키트(`design/`)나 사용자 지시에 없으면 사용자에게 확인한다. 미해결 질문 중 `blocking`이 남아
   있으면 적용 가정을 사용자에게 보여주고 진행 여부를 확인한다.
3. `design/`이 사용자 요구(목표 스택, 구조 요구)와 맞지 않으면 구현 전에 사용자와 조정하고 ADR로 남긴다.

## 진행 (10_plan.md의 태스크 순서 = 목표 설계 구성요소 순서)
각 태스크 T-NNN마다:
1. 태스크의 컨텍스트 팩(명세 ID + 설계 절)만 읽는다. 필요한 경우에만 다른 명세 ID를 추가로 연다.
2. **구조는 `design/`을 따른다.** 구성요소·모듈 이름·소스 배치는 설계의 것을 쓴다. 레거시의 파일 분할, 함수 분해,
   내부 이름(함수·변수·타입·클래스)을 옮겨 오지 않는다. 계약 식별자(03_interfaces, 04_data)만 원문 그대로 쓴다.
3. **동작은 명세를 정확히 지킨다.** 계약은 이름·포맷·바이트·순서·반올림·시간대·인코딩·오류코드까지 그대로, 규칙 BR·불변식
   INV·상태 SM·오류 ERR·결과 결정 알고리즘 ALG는 관측 결과가 같도록. 운영 설정 값이 기본값이어야 한다.
4. 해당 규칙의 테스트 벡터(TV-*)를 먼저 테스트로 옮기고 구현한다(TDD). `07_tests/golden`이 있으면 완료 기준에 맞춰 실행한다.
5. 명세가 모호하면: `trace.json`에서 그 ID의 `src`를 찾아 `legacy_ref/`(또는 레거시 코드)의 **그 위치만** 읽고, 얻은 답을
   새 설계의 언어로 구현한다. 레거시 코드 조각을 복사·번역하지 않는다. 확인한 사실과 결정은 `IMPLEMENTATION_NOTES.md`에
   ID와 함께 기록한다. 레거시 코드가 없으면 `09_open_questions.md`의 적용 가정을 따른다.
6. 설계와 다르게 구현해야 하면 이유를 ADR 형식으로 `IMPLEMENTATION_NOTES.md`에 남긴다.
7. 태스크 완료 시 진행 로그(`IMPLEMENTATION_PROGRESS.md`)에 결과·테스트 상태를 남긴다.

## 마무리
- 전체 테스트와 `07_tests` 골든 테스트를 모두 실행해 결과를 보고한다.
- 키트의 모든 계약(03_interfaces, 04_data) 목록을 하나씩 대조해 누락이 없는지 점검한다.
- 레거시 코드를 참고했다면 구조 독립성을 측정해 판정을 그대로 보고한다:
  `python3 kit/tools/structure_check.py <레거시 코드> <신규 코드> --detail`
  (계약 파일은 키트 `03_interfaces/files/`로 고정 — 다른 파일을 제외하지 않는다. 목표 LSS < 20, 함수 대응률 M4 < 10%.
  대응 함수로 나온 것은 이름을 바꾸는 것이 아니라 `design/`에 따라 다시 작성한다.)
- 키트와 다르게 구현한 부분, 남은 가정·위험을 요약한다.
